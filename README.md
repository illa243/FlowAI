# FlowAI

FlowAI 0.4.0 — локальний візуальний редактор Workflow для Codex-агентів. Поточна
версія працює з форматом Flow 2 і має сім спеціалізованих блоків для циклу
«уточнити промпт → виконати → перевірити → прийняти або повернути на переробку».
Кожен агентський блок має власну модель, інструкції, промпт, Codex-тред, робочі
папки та рівень доступу.

FlowAI не потребує OpenAI API-ключа: Codex використовує збережений вхід у ChatGPT.
Моделі GPT працюють у хмарі OpenAI, тому потрібен інтернет і доступний ліміт Codex у
вашому тарифі ChatGPT.

Повний посібник користувача й технічний опис: [DOCUMENTATION.md](DOCUMENTATION.md).
Стисла специфікація для AI, який складає Flow:
[FLOWAI_NODE_GUIDE.md](FLOWAI_NODE_GUIDE.md).

## Встановлення на Windows

1. Відкрийте PowerShell у цій папці.
2. Виконайте:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\install.ps1
   ```

3. Запустіть `start-flowai.cmd`.
4. У FlowAI натисніть **Увійти в ChatGPT** і завершіть вхід у браузері.

Якщо команда Codex доступна у `PATH`, авторизуватися також можна заздалегідь:

```powershell
codex login
```

Під час входу у FlowAI відкривається модальне вікно з єдиною кнопкою
**СКАСУВАТИ**; вона припиняє активну
OAuth-спробу в Codex. Після входу кнопка змінюється на локальний аватар і нік акаунта.
Поруч із ніком показується найменший доступний залишок лімітів у відсотках. Наведіть
курсор, щоб побачити пошту, відсоток і окремі вікна лімітів із часом їх скидання.
Показник оновлюється після виконання Flow та кожні п'ять хвилин. Повторне натискання
показує підтвердження виходу.

Після першого встановлення достатньо запускати `start-flowai.cmd` подвійним кліком.

## Швидкий старт

Після запуску виберіть **Файл → Новий** або натисніть `Ctrl+N`. FlowAI створить
готову схему:

```text
Entry prompt → Prompt Reviewer → Task Executor → Task Reviewer → Result
                                        ▲                          │
                                        └────────── FALSE ─────────┘
```

Окремий **Work Reviewer** без портів веде Markdown-протокол усіх проходів і після
завершення аналізує роботу блоків.

1. У **Entry prompt** введіть завдання та за потреби додайте файли.
2. У **Task Executor** виберіть модель і доступ до робочих папок.
3. У **Task Reviewer** перевірте блок-еталон і схему вердикту.
4. У **Result** налаштуйте ліміти гілок `TRUE` та `FALSE`. За потреби увімкніть
   **Очікувати підтвердження перед переходом**, щоб переглянути проміжні файли перед
   продовженням маршруту.
5. Натисніть **Run**.

Панель налаштувань Інспектора має назву **Parameters**. Натисніть напис
**Модель** або саме поле моделі, щоб відкрити список доступних моделей; назву
довільної сумісної моделі також можна ввести вручну.

У правому верхньому куті кожного великого текстового поля є компактна кнопка
розгортання. Вона відкриває вміст у максимізованому редакторі: **Застосувати**
повертає зміни в поле ноди, а **Скасувати** залишає початковий текст. Це доступно,
зокрема, для постійних інструкцій, промптів, JSON-схем і шаблону результату.

Готовий файл-приклад: [examples/review_loop.flowai.json](examples/review_loop.flowai.json).
Файли формату 1 не конвертуються автоматично через повну зміну набору блоків.

## Робочі середовища

Ліва панель зберігає список Flow-проєктів. Сірий індикатор означає, що проєкт ще
не завантажений, жовто-помаранчевий — завантажений у фоні, зелений — вибраний.
Flow продовжують працювати під час перемикання між середовищами.

Кнопка **Run** зелена, а **Stop** червона. Під час виконання вибраного проєкту
Run стає сірою, а Stop активується; для кожного середовища стан кнопок зберігається
окремо. Stop одразу перериває активного агента й скасовує наступні генерації лише
у вибраному проєкті.

Кнопка **Files** поруч відкриває історію файлів поточного запуску вибраного Flow.
Записи йдуть у порядку виконання: назва ноди та її ID, проміжні файли, а в кінці
результат ноди. Текст кожної групи має колір відповідної ноди; подвійний клік по
файлу відкриває його у стандартній програмі.

У **Налаштуваннях Flow** можна вибрати основну робочу папку всього проєкту та
додаткові папки, які успадковують усі агентські блоки. В Інспекторі можна додати
ще окремі папки лише для вибраного блока. Усі папки можна прибирати зі списків.

Списки середовищ і блоків автоматично стають горизонтальними, коли відповідна панель
ширша за свою висоту, та повертаються до вертикального вигляду у вузькій панелі.
Обидві панелі можна прикріплювати до будь-якого краю вікна й вільно розтягувати
по ширині. Заголовки dock-панелей і дубльований пояснювальний текст приховані:
у шарах залишено лише кнопки, списки, поля та журнал.

У від'єднаної панелі біля помітної червоної кнопки закриття доступна системна
кнопка розгортання. Вона розтягує модульне вікно на весь екран; повторне
натискання повертає попередній розмір.

Якщо панель прикріплена зверху або знизу, тягніть вузький вертикальний маркер на
її правому краї, щоб зменшувати чи збільшувати ширину. Подвійний клік по маркеру
повертає панель на всю ширину. Значення зберігається між запусками FlowAI.
Позиція, dock-область, плаваючий стан і розмір усіх панелей автоматично
записуються невдовзі після зміни, а не лише під час закриття програми.

Натисніть `F2`, коли вибраний блок або елемент списку середовищ, щоб змінити його
назву.

`Ctrl+Z` скасовує останню зміну поточного Flow, а `Ctrl+Y` повертає скасовану
зміну. Кожне робоче середовище має власну історію редагування.

Справа на картці показується анімований індикатор виконання, велика крапка нового
фонового результату, знак помилки або трикутник очікування. Flow стає на
паузу, коли гілка блоку Result вичерпала свій ліміт проходів. Уже завершені
блоки після відповіді повторно не запускаються.

На активному блоці біля назви показується етап `1/6`, а внизу — назва поточного
етапу з легким пульсуванням. Біля моделі також видно вибраний тип міркування.
Під час виконання таймер оновлюється, а блок м’яко пульсує зеленим. Кожен повторний
прохід блока створює окремий таймер з нуля під попереднім, без додавання часу.

Під час роботи ноди її незмінні параметри блокуються. У Result ліміти TRUE/FALSE
та прапорець очікування можна змінювати наживо — Runner одразу враховує нові
значення. Колесо миші не змінює значення полів у Parameters.

Зображення у вкладеннях показуються як мініатюри й відкриваються на весь екран
лівим кліком. Для інших файлів видно лише назву. Контекстне меню правої кнопки
дозволяє відкрити розташування у Провіднику, скопіювати шлях або вилучити файл зі
списку.

Консольні повідомлення мають формат `id ноди: повідомлення` і колір активної
ноди; шляхи створених файлів підкреслюються. Після завершення Flow або очікування
підтвердження у неактивному вікні FlowAI показує Windows-сповіщення. Клік по ньому
відкриває потрібний проєкт і фокусує відповідний блок.

Під час блокування Windows або переходу ПК у сон усі активні проєкти переходять
у кероване очікування. Після розблокування чи пробудження вони продовжують роботу.
Якщо хоча б один Flow активний, закриття FlowAI потребує окремого підтвердження.

Після завершення повний машинозчитуваний журнал автоматично зберігається у папку
`runs` поруч із файлом Flow. Якщо Flow ще не збережений, використовується папка
програми.

Загальний журнал програми пишеться у `%LOCALAPPDATA%\FlowAI\logs\flowai.log`,
а необроблені винятки, аварійні завершення та дампи потоків при зависанні — окремо
у `%LOCALAPPDATA%\FlowAI\logs\crash.log`. Папку можна відкрити через меню
**Допомога → Відкрити папку логів**. Старі журнали автоматично ротуються у файли
з суфіксами `.1`, `.2` тощо.

## З’єднання

Щоб з’єднати блоки, затисніть круглий порт справа вихідного блока, протягніть
пунктирну криву до порту зліва цільового блока й відпустіть. У **Result** виберіть
зелений порт `TRUE` або червоний `FALSE`. Також працює попередній спосіб: клік по
виходу, потім клік по входу. Коли крива потрапляє на допустимий вхід, порт
загоряється; після відведення курсора підсвічування зникає. Після цього виділіть
лінію та налаштуйте:

Подвійний клік у будь-якому місці готового зв’язку додає фіолетову керовану точку.
Перетягуйте її, щоб вигнути лінію та прокласти зв’язок в обхід інших блоків.
Виділену точку можна прибрати клавішею `Delete` або `Backspace`; її координати
зберігаються у файлі Flow.

Для переміщення по великому полотну затисніть праву кнопку миші та рухайте мишу.

- **Що передати** — `data`, `data.summary`, `text` або `$` для всього результату;
- **Вхідна змінна** — ім’я, доступне у наступному блоці;
- **Умова переходу** — наприклад `source.status == "success"`;
- **Перетворення** — необов’язковий шаблон із `{{value}}`.

У промптах і шаблонах доступні `{{inputs}}` та іменовані змінні, наприклад
`{{research}}` або `{{plan.steps}}`.

## Блоки

| Блок | Призначення |
| --- | --- |
| **Entry prompt** | Вхідний промпт, файли і картинки |
| **Tasks Manager** | Послідовно видає список завдань через `NEXT`, приймає підтвердження через `Result: TRUE` і завершує чергу через `DONE` |
| **Prompt Reviewer** | Покращує промпт, бачачи весь подальший ланцюг блоків |
| **Task Executor** | Виконує задачу; між ітераціями може продовжувати той самий Codex-тред |
| **Task Reviewer** | Виносить вердикт за схемою `{verdict, score, candidate_path, reason, must_fix}` |
| **Result** | Розгалужує потік на TRUE/FALSE з лімітами проходів і зберігає результат |
| **Work Reviewer** | Блок без портів: веде протокол роботи Flow і аналізує його в кінці |

Гілка `FALSE` блока Result повертає задачу виконавцю на переробку. Гілка `TRUE`
може повертатися до **Tasks Manager**, щоб позначити поточне завдання виконаним і
видати наступне. Це два дозволені види циклу через Result. Коли гілка вичерпує
свій ліміт проходів, Flow зупиняється,
блок блимає, а користувач може додати спроби, піти іншою гілкою або зупинити
запуск.

Для точних циклів переробки використовуйте
`Result: data.retry_context → Task Executor: prompt`: структуровані `must_fix`,
останній висновок і фактичний `candidate_path` передаються без перетворення на
довгий текст. Файлові Flow також можуть вимагати конкретний свіжий артефакт і
контролювати, що вихідний файл не був змінений.

Режим пам’яті **Той самий тред** відновлює Codex-тред блока між ітераціями.
Режим **Новий тред щоразу** починає кожен прохід із чистого контексту. Це не те
саме, що **Повторні спроби**: повтор застосовується після технічної помилки, а
ітерація виникає при повторному проходженні схеми.

Кожен запуск створює окрему папку `runs\<час>\` із `flowai-run.json`. Якщо у Flow
є **Work Reviewer**, там також з’являються `work-review.md` і
`work-review-report.md`.

## Безпека

- За замовчуванням агент обмежений вибраним sandbox.
- Перед запуском `full-access` FlowAI показує окреме попередження.
- Дані входу ChatGPT не записуються у `.flowai.json`.
- Не публікуйте файл `~/.codex/auth.json` і не передавайте його іншим людям.

## Розробка і тести

```powershell
.\.venv\Scripts\python.exe -m pytest
$env:QT_QPA_PLATFORM="offscreen"
.\.venv\Scripts\python.exe -m flowai
```

Для локальної перевірки Runner без звернення до Codex встановіть
`FLOWAI_FAKE_CODEX=1`.
